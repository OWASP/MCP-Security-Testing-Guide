# Appendix F: Testing Tools

Tool **categories** — not products — that the tests in [Chapter 3](<03. MCP Threats and Attack Patterns/3. MCP Threats and Attack Patterns.md>) expect you to have available. Consistent with the vendor-neutral rule in [CONTRIBUTING](CONTRIBUTING.md), this appendix names capabilities so that any equivalent tool satisfies the test.

Pick the category the test calls for. If your tooling does not cover a category, that gap is itself a finding about your readiness to assess MCP systems.

## Client and host utilities

| Category | What it gives you | Used by |
| --- | --- | --- |
| MCP client utility that can send raw JSON-RPC | Reproducible `tools/list`, `tools/call`, `resources/read`, `prompts/get` requests outside the model's control | All runtime tests |
| Host configuration inspector | Reads the real config files (including workspace-level config) rather than the UI's server list | `INFO`, `CONF`, `GOV` |
| Tool-manifest snapshot and diff tooling | Detects description, schema and annotation drift between two points in time | `TOOL`, `SUPP` |
| Transport test client | Speaks `stdio` and Streamable HTTP directly, plus the deprecated 2024-11-05 HTTP+SSE transport when testing a legacy server, so transport-level checks do not depend on a host | `CONF`, `TRNS` |

## Interception and traffic analysis

| Category | What it gives you | Used by |
| --- | --- | --- |
| HTTP/TLS interception proxy | Sees request and response bodies, headers, session identifiers and redirects for remote transports | `AUTHN`, `TRNS`, `GW` |
| Local process and file-access tracer | Shows what a locally spawned server reads, writes and executes, and under which identity | `CONF`, `RSRC`, `SECR` |
| Egress observer | Correlates tool invocation with outbound destinations | `GW`, `TOOL`, `PRVC` |

## Dependency, provenance and supply chain

| Category | What it gives you | Used by |
| --- | --- | --- |
| Dependency and vulnerability scanner for the ecosystems in use | Known-vulnerable or unexpected packages in a server's dependency tree | `SUPP` |
| SBOM / AI-BOM generator | An inventory of components, models, prompts and datasets for review and drift detection | `SUPP`, `GOV` |
| Package provenance and integrity checker | Signature, attestation, digest pinning and registry-metadata verification | `SUPP` |
| Transparency-log client | Submits entries, fetches inclusion proofs and signed checkpoints, and searches a log by digest or identity | `SUPP` |
| Registry metadata comparator | Registry listing versus installed artifact — typosquats, namespace mismatches, version skew | `SUPP` |

## Detection, logging and response

| Category | What it gives you | Used by |
| --- | --- | --- |
| Structured log search over host, server and gateway logs | Reconstruction of a tool call sequence with user, parameters and result | `LOG`, `SECR` |
| SIEM query language access (KQL, SPL, and equivalents) | Turns the detection examples in `3.12` into working queries | `LOG` |
| Detection-rule authoring (Sigma-style rules, YARA for metadata) | Tool-call and metadata-change detections that survive a tool change | `LOG`, `TOOL` |
| Alerting and case management | Proves a detection actually fires and is routed to someone | `LOG`, `GOV` |

## Policy and control testing

| Category | What it gives you | Used by |
| --- | --- | --- |
| Policy-as-code test harness | Asserts allow/deny decisions against the documented policy, with stable reason codes | `GOV`, `GW`, `AUTHZ` |
| Sandbox / container runtime with resource and egress limits | Bounds destructive and concurrency tests | `CONF`, `ABUS`, `TOOL` |
| Secret scanner | Detects secrets in configs, logs, traces and tool outputs | `SECR`, `LOG` |
| Rate-limit and timeout exercise tooling | Tests throttling, retry behaviour and loop protection | `ABUS`, `GW`, `TRNS` |
| PII discovery and classification | Finds personal data in resources and tool outputs | `PRVC`, `RSRC` |

## Evidence handling

Whatever the category, the evidence rules are the same: capture the request, the response, the identity, the timestamp, and the policy decision; redact secrets; record the configuration state at the time of the test. A finding without reproducible evidence is an opinion — see the [finding template](<03. MCP Threats and Attack Patterns/test-case-format.md#mcp-red-team-finding-template>).
